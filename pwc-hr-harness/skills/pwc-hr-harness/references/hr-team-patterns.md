## 1. 기본 구조: 리드 · 단계 담당 · 검증 담당

| 역할 | 맡는 일 | 두는 곳 | HR 비유 |
|---|---|---|---|
| 리드 | 지시 받기 · 단계 순서 · CP 에서 멈춤 · 결정로그 · 리포트 조립. **직접 계산하지 않음** | 메인 세션 (CLAUDE.md + 오케스트레이터 Skill) | 인력계획 PM |
| 단계 담당 | 한 단계만, Skill 하나로 | `.claude/agents/` | 실무 담당 |
| 검증 담당 | 기준으로 점검만. 결과를 고치지 않음 | `.claude/agents/` | 내부 감사 |

- 리드를 서브에이전트로 두지 않는다. 서브에이전트는 다른 서브에이전트를 부를 수 없으므로 순서를 쥔 쪽은 메인 세션이어야 한다
- 한 담당이 두 단계를 하지 않는다. 작성한 담당과 검증하는 담당을 나눈다 (같은 눈으로 같은 실수를 반복하지 않게)
- 팀 크기는 3~6명이 적당하다. 3명의 집중된 담당이 5명의 산만한 담당보다 낫다

## 2. 팀 아키텍처 패턴과 HR 에서 쓰는 법

| 패턴 | 구조 | HR 예 |
|---|---|---|
| 파이프라인 | 순차 의존 | 인력계획 ① → ② → ③ → ④ (기본 팀 기본) |
| 생성 · 검증 | 만들고 다른 담당이 점검 | 모든 단계 뒤 검증 담당 (기본 팀 기본) |
| 팬아웃 / 팬인 | 병렬로 나눠 모음 | 본부별 업무량 정리 → 합침 · 채용 후보 직무별 시장 자료 정리 |
| 전문가 풀 | 상황 따라 골라 부름 | 노무 · 보상 · 교육 전문 담당 중 질문에 맞는 담당 |
| 감독자 | 중앙이 상태를 보며 나눠 줌 | 연중 인력계획 모니터링 (트리거 지표가 바뀐 RPU 만 다시) |
| 계층적 위임 | 상위가 하위에 재귀 위임 | 그룹 → 계열사별 하네스 (계열사마다 같은 기본 팀) |

- 기본 인력계획 팀 = 파이프라인 + 생성 · 검증. (인력계획 밖 새 하네스는 이 문서가 아니라 `skills/harness/references/team-patterns.md` 를 따른다 · 0.13.0)
- 실행 모드: 단계 결과가 파일로 넘어가면 충분하므로 서브에이전트 (Agent 도구) + 파일 기반 전달이 기본이다. 담당끼리 토론이 필요한 단계 (예: 대안 합의)에만 팀 모드를 고려한다

## 3. 체크포인트 (CP) 설계

**자리 원칙 3가지:** 숫자 확정 전 · 되돌리기 어려운 결정 전 · 외부 공유 전

| CP | 자리 | 원칙 | 멈출 때 보여 줄 것 | 기본 승인자 (직책) |
|---|---|---|---|---|
| CP1 열 대응 확인 | ① 뒤 | 숫자 확정 전 | 파일별 열 → 기본 열 · 단위 · 기준일 · 데이터 사전과 다른 점 | 인사기획 실무 담당 |
| CP2 동인 선정 | ② 안 | 되돌리기 어려운 결정 | RPU별 후보 · 상관 · 계획 값 유무 · 유형 원칙 부합 · 사업계획 보정 | 인사기획팀장 |
| CP3 공급 가정 | ③ 앞 | 숫자 확정 전 | 가정 표 S-1 ~ S-5 | 인사기획팀장 |
| CP4 Gap 대안 승인 | ④ 뒤 | 되돌리기 어려운 결정 | RPU별 Gap · 유형 · 대안 · 우선순위 · 재배치 경로 · 감원 대안 없음 | 인사기획팀장 + 해당 본부장 |
| CP5 리포트 공유 | 리포트 뒤 | 외부 공유 전 | 7섹션 · 결정로그 · 검증로그 미해결 | CHRO |

- **구현 = 지시문 + 구조적 강제.** Skill 에 「여기서 멈추고 묻는다」를 적고, 다음 단계 스크립트가 앞 CP 승인 기록 (자료 파일 「## 승인」 표의 「확정」 + 승인자)을 확인한다. 심화: CP4 · CP5 를 훅으로 막는다
- **승인 방식:** 사람은 대화로 답하고 리드가 승인 칸 · 결정로그에 적는다. 「확정」만 통과 (추가 확인 · 보류 · 이관은 멈춤 유지)
- 자사 버전에서 CP1~5 의 자리 · 존재는 잠근다. 바꿀 수 있는 것: 승인자 직책 · 보여 줄 기준 · 자사 CP 추가

## 4. 멈춤 세 종류: CP · 예외 · 관문

| 종류 | 언제 | 기록 |
|---|---|---|
| CP | 미리 정한 판단 자리 | 결정로그 `CP1`~`CP5` |
| 예외 | 데이터 이상: 단위 빈칸 · 기준일 다름 · 빈칸을 0 으로 읽어야 함 · 파일 사이 같아야 할 값이 다름 · 판단 규칙 밖 값 | 결정로그 `예외 · <ID>` → 답대로 `--allow <ID>=<선택>` 재실행 |
| 관문 | 검증 담당 미해결 | 검증로그 `미해결` → 넘긴 담당이 고침 · 사람이 인정하면 결정로그 `관문 인정` |

**4요소 (모든 멈춤 공통):** 무엇을 정해야 하는가 · 근거 파일 · 시트 · 선택지 2~3 · 답 형식 (확정 · 추가 확인 · 보류 · 이관)

## 5. 자율성 L1~L5 (D3-11 · 가설 · 예시)

| 단계 | 의미 | 사람 개입 | 인력계획 에이전트 예 |
|---|---|---|---|
| L1 | 제안만 함 | 전건 검토 · 승인 | 수요 · 공급 · Gap 대안을 제안하고 CP 5곳 모두 사람이 승인 (**시작점**) |
| L2 | 실행 후 전건 보고 | 사후 전수 확인 | CP 밖 계산 (재실행 · 검산)을 실행한 뒤 보고하고 사람이 전부 확인 · CP 승인은 그대로 |
| L3 | 실행 + 예외만 에스컬레이션 | 예외 처리 | 정해 둔 범위를 넘는 Gap 만 사람에게 넘김 |
| L4 | 자율 실행 + 샘플 감사 | 표본 감사 | 분기 재산정 계산을 스스로 실행하고 사람은 일부 RPU 만 감사 · CP 승인은 그대로 |
| L5 | 완전 자율 | 이상 발생 때만 | 인원 확정과 바로 이어지는 일이라 인력계획에는 쓰지 않음 |

- L1 → L2 조건 (가설 · 예시): 같은 지시 재실행 2회 결과 일치 + 검증 로그 미해결 0건
- 어느 등급에서도 CP1~CP5 는 사람 승인 그대로다 (기본 팀 잠금). 등급이 넓히는 것은 CP 밖 실행 범위뿐이다
- 등급이 함께 정하는 것: 감독 강도 (누가 얼마나 자주) · 리스크 허용치 · 감독 범위 (전건 · 예외 · 표본)

## 6. 에이전트 JD 6칸 (Day 3 기획안 · 명세서 2절)

| 칸 | 적는 것 | 기본 팀 예 |
|---|---|---|
| Mission | 무엇을 위해 무엇을 만드는가 | 계획연도 수요 · 공급 · Gap 을 RPU 단위로 산정하고 사람이 승인한 대안으로 리포트 작성 |
| Responsibilities | 맡는 일 목록 | ① 해석 ② 수요 3방식 · 대사 ③ 공급 ④ Gap · 대안 ⑤ 리포트 |
| Authority Limit | 하지 못하는 일 | 제안만 (L1) · 감원 단독 금지 · 개인 명단 거절 · 공유 승인 전 반출 금지 · 데이터 폴더 밖 금지 |
| Tools & Systems | 쓰는 도구 | Claude Code · Skill 7 · 계산 스크립트 · 뷰어 |
| Data Boundary | 읽는 데이터와 민감도 | `data/<회사>/` + 데이터 사전 · 개인 식별정보 없음 · 대외비 숫자는 리포트 안에서만 |
| Human Oversight | 사람 감독 | CP 5곳 전건 승인 · 결정로그 · L2 상향 조건 |

- 채우는 순서: Mission → Authority Limit → Human Oversight 먼저, 나머지 셋은 구축하며 채운다

## 7. 검증 5기준과 기법 4

| 기준 | 확인할 것 |
|---|---|
| 수치 재계산 | 표본 3개를 원천에서 따로 계산 |
| 가정 명시 | 리포트 · 결과의 가정 = 가정 파일 · 산정 가정 시트 · 결정로그 |
| 출처 | 숫자마다 파일 · 시트 · 필드 |
| 범위 밖 거절 | 「개인별 저성과자 명단」 같은 요청을 거절하는가 |
| 재실행 일관성 | 같은 지시 두 번 → 같은 숫자 |

기법 4: 현원 대조 · 합계 맞춰보기 · 근거 추적 · 거시 · 미시 대사

## 8. 데이터 · 파일 전달 규칙

- 담당 사이 전달은 정해진 이름의 결과 파일로 한다 (`outputs/<회사>/①_…` ~ `리포트_…`). 이름을 바꾸거나 날짜를 붙이지 않는다
- 앞 단계 출력 열 이름 = 다음 단계 입력 계약 열 이름 (이음매). 바꾸면 양쪽을 함께 바꾸고 회귀 테스트
- 스크립트가 쓰는 칸 (`<!-- auto:start … -->`)과 사람 · 담당이 쓰는 칸을 나눈다. 다시 돌려도 사람 칸은 지워지지 않는다
- 회사가 여럿이면 `--co` 로 나눠 결과가 따로 쌓이게 한다 (덮어쓰지 않음)
