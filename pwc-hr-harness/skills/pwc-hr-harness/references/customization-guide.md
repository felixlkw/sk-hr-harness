## 1. 바꾸는 것 / 바꾸지 않는 것

| 구분 | 항목 | 어떻게 |
|---|---|---|
| 바꿈 (데이터) | `data/자사/` 파일 · 열 이름 대응 · 자사 데이터 사전 | `열이름_대응.json` · `양식/데이터사전_빈양식.md` |
| 바꿈 (설정) | 기준 연도 · 계획 연도 · 이력 연도 · 승인자 직책 · FTE 검증 범위 | `.claude/hr-lib/config.json` |
| 바꿈 (변형 한 칸) | 동인 · 계획 단위 · Gap 우선순위 기준 · 리포트 양식 중 하나 | 3절 표의 자리만 |
| 바꿈 (추가) | 자사 CP (예: 노사 협의 전 확인) · 자사 판단 규칙 한 줄 | `wfp-lead` CP 표 · Skill 판단 규칙 (출처 「회사 기준」) |
| **잠금** | CP1~CP5 자리 · 존재 · CLAUDE.md 「업무 범위 · 금지」 · 감원 단독 금지 · 데이터 사전 공통 규칙 · 스크립트 CP 강제 · 검증 담당 분리 · `hrlib.py` | 바꾸지 않음 (`customize.py lock` 검사 · 순서 변경은 규칙상 금지지만 lock 은 삭제만 잡음) |

- 바뀐 파일 셈: `lock` 「changed」 · `diff` · 뷰어 「기본 대비 변경점」이 같은 셈을 쓴다 (CLAUDE.md + `.claude/` 아래 · hr-lib 은 `config.json` 만 · `settings.local.json` · baselines 제외 · 들여쓰기만 다른 JSON 은 같음). 변형 한 칸 = 보통 「규칙 한 줄 (Skill) + 변경 이력 한 행 (CLAUDE.md)」 두 파일

### 기본 팀이 기본으로 막는 것 · 막지 않는 것 (사내 이전 때 확인)

| 구분 | 무엇 | 사내에서 할 일 |
|---|---|---|
| 막음 (스크립트) | 앞 CP 승인 없이 다음 단계 계산 (`require_cp` · CP1~CP5 만) · 빈칸 = 0 · 기준일 섞기 · 감원 단독 · 검증 미해결 진행 | 그대로 둠 (잠금) |
| 규칙만 (지시문) | 데이터 폴더 밖 읽기 · 인터넷 검색 · 개인 명단 · 리포트 반출 (CP5 전) | 검증 「범위 밖 거절」 행동 테스트로 확인 |
| 막지 않음 | 외부 전송 (Bash) · 결과 파일 손 수정 · 개인정보 열 감지 · 자사 CP 의 스크립트 멈춤 | 훅 없음 · 담당 도구에 Bash 있음 → 훅 · 권한 설정 · 사내 정책으로 막음 (뷰어 「하네스」 › 훅 · 권한 후보에서 요청으로 만들 수 있음 · 작업 폴더 `.claude/settings.json` 에 둠) |

## 2. 데이터 연결 · 없을 때 대체

1. 자사 파일을 `data/자사/` 에 넣는다 (K-Co. 파일 6종 중 있는 것만)
2. `step1.py scan --co 자사` → `①_열대응표.md` 에서 「없는 열」 「다른 이름」을 본다
3. 이름만 다르면 `data/자사/열이름_대응.json`:
   ```json
   { "RPU 코드": "조직코드", "계": "인원", "자발퇴직": "자진퇴사" }
   ```
4. 표 자체가 없으면 아래 대체 (가정 표 · 결정로그에 「대체」로 남김)

| 기본 파일 | 없을 때 대체 | 영향 |
|---|---|---|
| 1 사업계획 | 경영계획 보고서 · 사업보고서 (공시 수준 숫자) | 방식 A 시나리오 · 보정 근거 |
| 2 연도별 추이 | 공시 수준 매출 · 영업이익 · 인원 · 인건비 5개년 | 방식 A |
| 3 입퇴사 이력 | 연도별 입사 · 퇴사 · 정년 요약표 (`--allow 퇴직빈칸=요약` 방식) | 공급 퇴직률 근사 |
| 4 업무량 조사 | 본인 팀 업무를 직접 기입 (대분류 · 업무 · 주기 · 시간 · 판정) | 방식 C 범위 축소 |
| 5 스킬 인벤토리 | 팀장 면담으로 RPU별 보유 수준 3단 판정 | Build 판정 「추가 확인」 |
| 6 인력동인 시계열 | 본인 조직 1~2개 RPU 동인 후보 + 최근 3개년 값 (기억 · 추정 표시) | 방식 B 일부 RPU 만 |

- 실데이터는 개인 식별정보 없이 집계 단위로만 넣는다. 개인 단위 행이 있으면 계산 전에 멈추고 묻는다

### 2-1. 자사 파일이 없을 때: 가상 데이터 만들기

자사 데이터 항목 (열 이름)과 대략의 규모만 알 때, 기본 6종 구조의 가상 데이터를 만들어 같은 순서로 연습한다.

| 무엇 | 내용 |
|---|---|
| 입력 | `data/<폴더>/가상데이터_설정.json` (양식 `양식/가상데이터_설정_예.json`): 회사 이름 · 기준일 · 전체 인원 · RPU (코드 · 이름 · 유형 · 본부 · 인원) · 열이름_대응 · 사업계획 요점 · 시드 + 선택 칸 (아래 표) |
| 자사 조건 카드 (선택 도우미) | 회사 특성을 먼저 정리하고 싶은 사람만 `양식/자사조건카드.md` 7칸을 채운다 (0.11.0 부터는 회사 적용 도우미 · 모드 F 가 같은 칸을 질문으로 물음). 채웠으면 리드가 설정 파일로 옮기고 **빈 칸만** 묻는다 (Day 3 은 보통 「가상 데이터로 회사 폴더 만들어 줘 … 회사 이름 X」 한 문장으로 설정을 만듦) (카드 「→ 가상데이터_설정 어느 칸」 열). K-Co. 예시 값은 `양식/K-co_조건예시.json` (키트 `gen_kco_examples.py` 가 키트 데이터 · 기본 팀 실행 결과에서 뽑음) · K-Co. 와 같은 조건의 설정은 `양식/가상데이터_설정_K-co예.json` |
| 빈 칸 | K-Co. 값을 비율로 맞춰 채움 (인원을 비운 RPU = 같은 유형 K-Co. RPU 인원 비율 · RPU 목록이 비면 K-Co. 20개 구조) |
| 만드는 법 | RPU 마다 같은 유형의 K-Co. RPU 하나를 원천으로 골라 (이름이 가장 비슷한 것 · 「원천」 칸으로 지정 가능) 인원 배율로 직급 · 연령 · 퇴직률 · 업무량 (FTE ÷ 현원) · 스킬 충족률 · 동인 증가율을 옮긴다. 매출 · 이익 · 인건비 = K-Co. 값 × 인원 배율 |
| 결정적 | 같은 설정 + 같은 시드 = 같은 내용 (표시 파일 「내용지문」). LLM 이 숫자를 만들지 않는다 |
| 만들지 않는 것 | 성명 · 사번 · 생년월일 등 개인 식별 열 · 사람 단위 행 (모든 행은 RPU · 직급 집계) · 신설 조직의 현원 행 (사업 이벤트는 파일 1 문장으로만 · 결정 수요 별도 줄) |
| 가상 표시 | `data/<폴더>/_가상데이터.json` · xlsx 문서 속성과 2행 안내문 · 리포트 첫 줄 「가상 데이터로 만든 결과 · 실제 판단에 쓰지 않음」 · 뷰어 상단 배너 · 표시 파일이 빠지면 검증 관문 |
| 멈춤 | `data/<폴더>/` 에 다른 파일이 있으면 덮지 않음 (전에 만든 가상 데이터만 `--replace-virtual` 로 다시 만듦 · 사람이 「다시 만들어 줘」라고 할 때만 · 기본 파일 새 판을 사람이 넣었으면 다시 만들지 않고 그 파일로 영향받는 단계부터 다시 돌림) · 함께 둘 수 있는 것: README · 설정 파일 · .gitkeep · 빈 데이터 사전 · `추가_*` (다시 만들어도 지우지 않음) · 설정이 동인 원칙에 어긋나면 멈춤 (Value Center 에 매출 같은 회사 전체 실적 · 계획 값 없는 동인 · 기존 RPU 와 겹치는 사업 이벤트 코드) |

**선택 칸 (0.10.0 · 비우면 지금처럼 K-Co. 값 · 빈 칸만이면 내용 지문이 예전 판과 같음):**

| 칸 | 적는 것 | 들어가는 곳 |
|---|---|---|
| 성장 시나리오 | 기준 매출 (억 원) · 보수 / 기본 / 낙관 「연평균 성장률 (%)」 또는 「계획 매출 (억 원)」 · 계획 영업이익률 (%) | 파일 1 · 1절 · 파일 2 연도별 추이 (기본 성장률로 과거 5년 매출을 기울임 · 이익 = 매출 × K-Co. 이익률) · 표시 파일 「사업계획 숫자」 |
| 사업 이벤트 | 신설 조직마다 코드 (새 코드) · 이름 · 유형 · 본부 · 가동 · 확보 (YYYY-MM · 비우면 가동 12개월 전) · 인원 · 구성 · 근거 | 파일 1 · 2절 (K-Co. 「3공장 신설」 문장 꼴) · 4절 재배치 문장 · 표시 파일 「사업 이벤트」 (②_수요파라미터 4 · 5절 행 꼴) |
| 동인 | RPU 별 주 동인 하나: 이름 · 단위 · 기준 값 · 계획 증가율 (%) 또는 계획 값 · 바꿀 후보 | 파일 6 조직별 인력동인 시계열 그 행 (원천 모양을 기준 값에 맞춤) · 파일 1 · 2절 |
| 추가 동인 | RPU 별 후보 행: 이름 · 단위 · 기준 값 (필수) · 계획 증가율 (%) 또는 계획 값 (필수) | 파일 6 행 추가 (그 RPU 인원 추이 모양 · 시드) → CP2 후보 |
| AI 범위 | RPU 유형 또는 RPU 코드 목록 | 파일 1 · 3절 · 표시 파일 「AI 적용 RPU」 (②_수요파라미터 3절 AI 적용 ○ 근거) |
| 인건비 인상률 (%) | 계획 연도 인상률 | 파일 1 · 4절 · 표시 파일 「사업계획 숫자」 |

### 2-2. 추가 데이터 3갈래 (기본 6종 밖 · `양식/추가데이터_정의서.md`)

| 갈래 | 예 | 어떻게 | 코드 |
|---|---|---|---|
| ① 동인으로 | 수주 건수 · 설비 수 · 고객 수 · 프로젝트 수 | 가상: 설정 「추가 동인」 · 실데이터: 파일 6 조직별 인력동인 시계열에 행 추가 → CP2 후보 | 필요 없음 |
| ② 판단 근거로 | 교육 이수 · 자격 보유 · 외주 · 도급 인원 · 채용 소요 기간 · 내부 이동 | `data/<폴더>/추가_<이름>.xlsx` → `step1.py scan` 이 기본 표에 대응시키지 않고 `①_열대응표.md` 「추가 자료 (계산에 안 씀 · 근거로 인용 가능)」 절에 파일 · 시트 · 열로 보고 → 담당이 판단 칸 · 4B 대안 근거에 「회사 기준 · 파일명」으로 인용 (wfp-step1-strategy · wfp-step4-gap 판단 규칙) · 더 구체적인 인용 규칙은 Skill 판단 규칙 한 줄 개정 | 필요 없음 |
| ③ 계산으로 (심화) | 초과근무로 업무량 보정 · 외주 인원을 Borrow 가능 인원으로 | 새 계산 스크립트 + Skill · K-Co. 회귀 시험 · 강사 시연 1건 | 필요 |

- `추가_` 로 시작하지 않은 파일도 기본 표에 맞는 시트가 하나도 없으면 「추가 자료」로 보고된다 (조용히 버리지 않음). 기본 파일 안의 보조 시트 (레벨 정의 · 유형 정의 등)는 넣지 않는다

```
python -X utf8 .claude/hr-lib/virtual_data.py --co <폴더> --dry-run   # RPU 원천 · 인원 미리 보기
python -X utf8 .claude/hr-lib/virtual_data.py --co <폴더>             # 만들기 → step1.py scan --co <폴더> → CP1
```
- 기준일 연도가 2025 가 아니면 B3 에서 `config.json` 연도를 맞춘다 (도구가 알려 줌)
- 가상 데이터 결과는 회사 판단에 쓰지 않는다. 실제 자사 파일이 생기면 다른 폴더 (이름 끝 `_실데이터` · 예: `data/자사_실데이터/` · `.gitignore` 견본이 저장소에서 뺌)에 넣고 처음부터 다시 돌린다 (`양식/실데이터_전환_점검표.md`)

## 3. 변형 메뉴 상세

### 3-1. 인력동인 교체 (CP2)
- 데이터 선택이면: 자사 `②_수요파라미터.md` 2절에서 ✓ 를 옮기고 근거를 적는다 (코드 · Skill 수정 없음)
- 회사 규칙이면 (예: 「영업 RPU 는 수주액을 쓴다」): `wfp-step2-demand/SKILL.md` 판단 규칙에 한 줄 + 출처 「회사 기준 · <문서>」
- 확인: 원칙 점검 「위반」 동인을 고르지 않았는가 (Value Center 에 회사 전체 실적 등)

### 3-2. 계획 단위 교체 (CP1)
- RPU 를 직무군 · 직급 단위로 바꿀 때: 자사 파일 「RPU 코드」 열에 새 단위 코드를 쓰고 (모든 파일 같은 코드), `wfp-step1-strategy/SKILL.md` 4절에 묶음 기준을 적는다
- RPU 원칙 유지: 빠지는 업무 없이 전 인원이 한 단위에 속함 · 코드는 해마다 유지

### 3-3. Gap 대안 우선순위 기준 교체 (CP4)
- `wfp-step4-gap/SKILL.md` 「조합 규칙」 · 「우선순위」 줄을 바꾼다 (예: 영향 × 시급성 → 비용 × 시급성)
- 감원 단독 금지 · 재배치 먼저는 그대로

### 3-4. 리포트 양식 교체 (CP5)
- `wfp-report/SKILL.md` 에 자사 보고 목차와 7섹션 대응을 적는다 (가정 · 검증 로그 섹션은 빠지지 않게)

### 3-5. 승인자 · 자사 CP
- 승인자: `config.json` → `"approvers": {"CP2": "인사팀장"}` (자사 예 · 가설) + `wfp-lead` CP 표 「기본 승인자」
- 자사 CP: `wfp-lead` CP 표에 `CP6 <이름> | 자리 | 자료 | 승인자` 행 추가 + 절차에 「여기서 멈춤」 한 줄

```json
  "hist_years": [2023, 2024, 2025], "series_years": [2021, 2022, 2023, 2024, 2025],
  "fte_band": [0.8, 1.2], "small_rpu": 40, "recon_bands": [0.03, 0.07],
  "approvers": {"CP1": "HR기획 담당", "CP5": "인사담당 임원"}
}
```
- approvers 값은 자사 예 · 가설이다 (회사 결재 규정에 맞춰 직책만 적음)
- 정년 도래 · 공급은 기준 연도 다음 두 해를 계산한다. 자사 자료 연도가 다르면 이 파일만 바꾼다

## 5. 회귀 테스트 읽는 법

- Day 2 끝 (K-Co. 리포트까지 끝난 뒤) `customize.py snapshot --co K-co --name 기준` → RPU 행 숫자 (합계 행 제외) · 합계 값 (결정 수요 · 공급 · Gap · 상승) · 방식 B · 대사 판정을 남김. snapshot 은 CP5 승인 여부를 보지 않는다 (리포트를 공유하는 일이 아님)
- 변형을 적용할 때마다 `customize.py regress --co K-co --name 기준` → `outputs/K-co/_회귀테스트.md`
- **차이 없음** = 변형이 기본 계산을 깨지 않음 (자사 데이터 · 자사 파라미터 변형은 보통 여기)
- **차이 있음** = 바꾼 규칙이 K-Co. 에도 걸림. 행마다 「의도한 변화인가」를 사람이 보고 결정로그에 「가정 변경」 또는 되돌림
- 비교 항목: 결정 수요 사람 · 디지털 · 방식 B · 대사 판정 · 2025 FTE · 공급 · Gap (RPU 행 + 합계). 동인을 바꾸면 결정 수요가 같아도 방식 B · 대사 판정 차이로 보임. 옛 기준 파일에 없는 항목은 비교하지 않음
- 결과 `_회귀테스트.md` 는 뷰어 「회귀」 화면 (「산출물」 › 회귀 에도)에 실린다
- 회귀 테스트는 승인된 파라미터 · 가정을 그대로 쓴다. CP 승인을 다시 받지 않는 대신, 결과는 사본에서만 만들고 원래 결과를 덮지 않는다
