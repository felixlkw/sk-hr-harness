# 회사 특성 정리 (참고 · 파일 이름 자사조건카드)

> 참고: Day 3 은 회사 적용 도우미 (`/hr-customize`) 가 이 칸들을 질문으로 하나씩 묻는다. 미리 정리해 두고 싶을 때만 쓴다 (채워 두면 도우미가 읽고 빈 칸만 묻는다).
>
> K-Co. 는 아래 7칸 조건으로 만든 회사다. 같은 칸을 우리 회사 것으로 바꾸면 우리 회사 가상 데이터가 된다.
> 실데이터 · 실명 · 내부 수치는 적지 않는다 (대략 · 가상 값). 모르는 칸은 비워 둔다 (K-Co. 비율로 채워짐).
> 「K-Co. 예시」 열은 키트 데이터와 기본 팀 실행 결과에서 자동으로 뽑은 값이다 (`양식/K-co_조건예시.json` · 손으로 고치지 않음). 예시를 그대로 옮겨 적지 말고 자사 값으로 고쳐 쓴다.

**다 채운 뒤 Claude 에게:** 「회사 특성 정리로 가상 데이터 만들어 줘 (회사 폴더 이름: <자사>)」
→ 리드가 이 카드를 `data/<자사>/가상데이터_설정.json` 으로 옮기고 **빈 칸만** 묻는다 → `virtual_data.py --dry-run` 으로 미리 보기 → 만들기 → `step1.py scan` → CP1

## 3. 자사 인력동인 (칸 4 자세히)

- RPU 마다 주 동인 하나 (이름 · 단위 · 기준 연도 값 · 계획 증가율 또는 계획 값). 비우면 K-Co. 원천 동인을 옮김
- Value Center (기술·전문 · 관리 지원)에 매출 같은 회사 전체 실적은 쓰지 않는다 · 계획 값이 없는 동인은 고르지 않는다 (동인 원칙)
- 자사가 따로 모으는 지표를 하나 더 넣고 싶으면 「추가 동인」 (CP2 후보로 잡힘 · 칸 5 의 ① 동인 갈래)

## 4. 쓰는 순서

1. 칸 1~7 을 채운다 (도우미 질문과 같은 칸 · 모르는 칸은 비움)
2. 칸 5 에 적은 추가 데이터는 `양식/추가데이터_정의서.md` 로 갈래 (동인 · 판단 근거 · 계산)를 정한다
3. 칸 7 (바꾸고 싶은 규칙)은 Day 3 오후 (선택) 고치기에서 말로 요청하거나 `양식/개정요청서.md` 로 옮긴다
4. 카드 → 설정 변환은 리드가 한다. 사람은 리드가 보여 주는 `--dry-run` 결과 (RPU 원천 · 인원 · 선택 설정 요약)를 확인한다
