# 하네스 개정 요청서 (선택 도우미)

> 선택 도우미: Day 3 오후 「(선택) 고치기」에서 말로 바로 요청해도 된다. 무엇을 · 왜 · 어디를 먼저 정리하고 싶을 때만 쓴다.
>
> 한 요청 = 한 변경. 뷰어 「하네스」 화면의 「수정」 → 「Claude 에게 맡길 문장 복사」와 같은 칸을 쓴다. 채운 뒤 Claude 에게 「/hr-customize 하네스 수정 요청」 + 이 표를 붙여 넣는다.

## 1. 요청

| 칸 | 적을 것 | 내 답 |
|---|---|---|
| 무엇을 | 바꿀 규칙 · 문장 한 줄 (예: 「④ 우선순위를 비용 × 시급성으로」 · 「추가_교육이수.xlsx 를 Build 대안 근거로 인용」) |  |
| 왜 | 자사 사정 · 근거 문서 (회사 기준 · 파일명) |  |
| 어느 층 | 설정 (`config.json` 연도 · 승인자) · 판단 규칙 (Skill 본문) · 계산 (스크립트 · 심화) 중 하나 |  |
| 어느 Agent · Skill | 예: `wfp-step4-gap` SKILL 「우선순위」 줄 · `wfp-gap` 에이전트 설명 · `wfp-step1-strategy` 판단 규칙 |  |
| 바꿀 내용 | 지금 문장 → 바꿀 문장 (뷰어에서 복사하면 diff 로 들어감) |  |
| 잠금 여부 | 🔒 잠금 칸을 건드리는가 (CP1~CP5 · 업무 범위 · 금지 · 감원 단독 금지 · 빈칸 ≠ 0 · 검증 분리 · 스크립트 CP 강제). 건드리면 Claude 가 적용 전에 멈추고 묻는다 | 예 · 아니오 |
| 회귀 기대 | K-Co. 로 다시 돌렸을 때: 「차이 없음」 (판단 규칙 · 자사 데이터 변형) 또는 「차이 있음 · 의도함」 (K-Co. 에도 걸리는 계산 변경 · 어느 숫자가 어떻게) |  |
| 행동 점검 | 정상 요청 1 · 경계 요청 1 (빈칸 · 기준일) · 범위 밖 요청 1 (개인 명단 · 인터넷 검색) 에 바뀐 하네스가 어떻게 답해야 하나 |  |

## 2. 적용 뒤 확인 (Claude 가 하고 결과를 적음)

| 확인 | 결과 |
|---|---|
| 잠금 검사 `customize.py lock` | 통과 · 위반 |
| K-Co. 회귀 `customize.py regress --co K-co --name 기준` | 차이 없음 · 차이 n건 (의도함 · 되돌림) |
| CLAUDE.md 변경 이력 한 행 | 날짜 · 무엇을 · 대상 · 사유 |
| 자사로 다시 실행 · 달라진 판단 | 어느 CP · 어느 행 · 무엇이 달라졌나 (발표 재료) |

## 3. 고치는 자리 3층 (참고)

| 층 | 자리 | 회귀 | Day 3 |
|---|---|---|---|
| 설정 | `.claude/hr-lib/config.json` (기준 · 계획 연도 · 승인자 직책) | 보통 차이 없음 | 누구나 |
| 판단 규칙 | `.claude/skills/<skill>/SKILL.md` 판단 규칙 · `.claude/agents/<담당>.md` 설명 | 숫자는 보통 차이 없음 · 행동 점검으로 확인 | (선택) 고치기 |
