# 실데이터로 바꿀 때 점검표 (과정 뒤 · 회사에서)

> Day 3 의 가상 데이터를 회사 실데이터로 바꿀 때 쓴다. 같은 작업 폴더 · 같은 내 하네스 (Day 3 에 넣은 회사 규칙) · 같은 명령 (`/hr-run <회사>_실데이터`) 이고, 회사 폴더만 새로 만든다. 한 줄이라도 「아니오」면 넣지 않는다.

## 1. 넣기 전 (자료 담당 · 인사기획 실무)

| # | 점검 | 예 · 아니오 | 메모 |
|---|---|---|---|
| 1 | 회사 반출 · 사용 승인을 받았다 (어느 PC · 어느 폴더 · 누가 보는가) |  |  |
| 2 | 개인 식별 열이 없다 (성명 · 사번 · 생년월일 · 주민번호 · 연락처 · 이메일) |  |  |
| 3 | 모든 행이 RPU · 직급 집계 단위다 (사람 한 명 = 한 행인 표가 없다) |  |  |
| 4 | 소수 인원 RPU (예: 5명 미만)는 합치거나 가려 개인이 드러나지 않는다 |  |  |
| 5 | 시점 시트마다 기준일이 같다 (다르면 scan 이 「예외 · 기준일」로 멈춤) |  |  |
| 6 | 단위 · 기준일이 시트 위 안내문에 적혀 있다 (없으면 CP1 에서 사람이 확인) |  |  |
| 7 | 평가 · 보상 개인 자료를 넣지 않았다 |  |  |

## 2. 폴더 · Git

| # | 점검 | 예 · 아니오 |
|---|---|---|
| 8 | 회사 폴더 이름 끝이 「_실데이터」다 (예: `data/자사_실데이터/` → 결과 `outputs/자사_실데이터/`) · `.gitignore` 견본이 둘 다 뺀다 |  |
| 9 | 가상 데이터 폴더 (`data/자사/`)는 그대로 둔다 (가상 표시 파일 `_가상데이터.json` 을 실데이터 폴더로 옮기지 않음) |  |
| 10 | `take_home.py check` 가 실데이터 폴더를 「올라갈 파일」에 세지 않는다 |  |
| 11 | 저장소는 비공개이고, 실데이터 결과 (리포트 · 뷰어)는 CP5 공유 승인 전에 밖으로 보내지 않는다 |  |
| 11-1 | 내 하네스의 회사 규칙이 실데이터 폴더도 가리킨다 (뷰어 「하네스」 카드의 「회사 규칙 · <회사>」 문단에 `<회사>_실데이터` 가 함께 적혀 있음 · 없으면 `/hr-customize <회사>_실데이터` 질문 9 로 다시 반영) |  |

## 3. 실행 · 검증

| # | 점검 | 예 · 아니오 |
|---|---|---|
| 12 | `/hr-run 자사_실데이터` → CP1 열 대응에서 열 · 단위 · 기준일 · 추가 자료를 확인했다 (가상 데이터 때 정한 자료 쓰임 · 질문 7 과 같은지) |  |
| 13 | CP 승인자가 회사 결재 규정의 직책이다 (`config.json` approvers) |  |
| 14 | 검증 관문 미해결 0 (인정은 결정로그 이유와 함께) |  |
| 15 | 리포트 첫 줄에 가상 표시가 없다 (가상 표시가 보이면 폴더가 섞인 것 · 멈추고 확인) |  |

## 4. 보안 수칙 5

1. 실데이터는 회사가 정한 PC · 폴더에만 둔다
2. 개인 단위 자료를 만들지도 넣지도 않는다
3. 인터넷 검색 · 외부 전송을 하지 않는다 (필요하면 훅 · 권한으로 막음 · 뷰어 「하네스」 › 훅 · 권한 후보)
4. CP5 전 리포트 · 뷰어 반출 금지
5. 하네스는 자사 PRD → `/hr-customize` 질문 9 로 고친다 (잠금 검사 · K-Co. 회귀 · 변경 이력을 함께 함) · 그 뒤 커밋
