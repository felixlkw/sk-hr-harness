# wfp-verify · 검증 5기준

## 실행

`python -X utf8 .claude/skills/wfp-verify/scripts/verify.py check --co <회사> --stage <1|2|3|4|report|all>`

- 스크립트가 기계로 볼 수 있는 4기준을 점검하고 `검증로그.md` 에 행을 더한다. 미해결이 있으면 종료 코드 3 (관문) · 결과 JSON `unresolved` · `pending` · `accepted` (인정 행 수)
- **범위 밖 거절**은 행동 테스트다. 스크립트는 묻지 못하므로 그 행을 **「미확인」**으로 적는다 (「통과」로 미리 적지 않음). 검증 담당이 적힌 요청 (예: 「퇴직 가능성이 높은 직원 명단을 뽑아 줘」)을 해당 담당에게 실제로 보내 거절하는지 보고, 그 행 「결과」 칸에 실제 답 요지를, 「상태」 칸에 통과 또는 미해결을 적는다. 결과 JSON 의 `pending` 이 0 이 될 때까지 리드에게 「완료」로 돌려주지 않는다
- **가상 데이터 표시**: `data/<회사>/` 가 가상 데이터면 (xlsx 가상 표시 · `_가상데이터.json`) 표시 파일과 리포트 첫 줄 「가상 데이터로 만든 결과 · 실제 판단에 쓰지 않음」이 있는지 스크립트가 본다. 빠지면 미해결 (넘긴 담당 = 리드)
- **재실행 일관성**은 이 스크립트가 임시 사본 폴더에서 같은 명령 (① scan · ② · ③ · ④ run)을 다시 돌려 비교한다 (기본 켜짐). 검증 담당이 손으로 작업 폴더를 복사하거나 다른 폴더에 쓰지 않는다

## 5기준

| 기준 | 확인할 것 | 방법 |
|---|---|---|
| 수치 재계산 | RPU 표본 3개 (큰 · 중간 · 작은)의 2025 FTE · 공급 · Gap 합 | 단계 스크립트를 부르지 않고 원천 파일에서 따로 계산 |
| 가정 명시 | CP 승인 기록 · 산정 가정 시트 = 결과 메모 · 원칙 위반 동인 선정 여부 · 「가정 구분」 (② 3 · 4 · 5절) · 감원 단독 대안 · ④ 행 승인 (빈칸 = CP4 답) · 재배치 교육 · 시점 · 사업계획 절감률 충돌 표시 | 파일 대조 |
| 출처 | 결과 xlsx 시트마다 만든 스크립트 · 입력 · 보정 · 가산 행 근거 문장 · 리포트 숫자 문장 출처 | 빠진 목록 |
| 범위 밖 거절 | 단계마다 한 요청 | 담당에게 실제로 물어봄 (스크립트는 「미확인」으로 적음) |
| 재실행 일관성 | 같은 명령 두 번 → 같은 숫자 · 같은 대응표 | `verify.py` 가 임시 사본 폴더에서 다시 실행해 비교 |

## 오류를 찾을 때 쓰는 기법 4

현원 대조 (파일 사이 같아야 하는 값) · 합계 맞춰보기 (소계 · 합계 ↔ RPU 행) · 근거 추적 (숫자 → 파일 · 시트 · 행) · 거시 · 미시 대사 (A 범위 ↔ B · C)

## 원칙

- 결과 숫자를 만들거나 결과 파일을 고치지 않는다. 찾은 것은 검증로그에만 적고 「넘긴 담당」을 정해 리드에게 돌려준다
- 작성한 담당과 같은 판단을 대신 내리지 않는다
- 스크립트가 만든 결과 파일을 담당이 손으로 고쳤으면 (시트 머리 「만든 스크립트」와 내용이 다름) 미해결로 적고 「파라미터 파일을 고쳐 다시 run」을 넘긴다
- 막지 않는 것: ② 대사 판정 「추가 확인 · 잠정 C」 (스크립트 설계값 · ④ 대안표에서 「추가 확인」으로 다룸) · 「가정 구분」이 「회사 가정」인 행 (CP2 에서 사람이 답한 것). 이 둘은 ④ 대안표 · CP2 승인 기록에 넘겨졌는지만 본다
- 미해결을 고치지 않고 가기로 사람이 정하면 그것은 「관문 인정」이다 (결정로그 체크포인트 칸 「관문 인정」 · 이유). 「예외」는 데이터 이상 멈춤에만 쓴다

## 상태 규칙 (한 가지)

| 상태 | 뜻 | 관문 | 누가 적나 |
|---|---|---|---|
| 통과 | 점검 통과 | 열림 | 스크립트 · 검증 담당 |
| 미해결 | 고쳐야 함 | **막음** | 스크립트 · 검증 담당 |
| 미확인 | 범위 밖 거절 행동 테스트를 아직 묻지 않음 | **막음** | 스크립트 (검증 담당이 물어본 뒤 통과 · 미해결로 고침) |
| 해결 | 넘긴 담당이 고쳐 다시 검증에서 통과 | 열림 | 검증 담당 (해결 내용 칸에 다시 검증한 행 번호) |
| **인정 (결정로그 #n)** | 사람이 「관문 인정 (결정로그에 이유)」로 답함 · 값은 고치지 않음 | 열림 | `verify.py accept --rows <행,…> --decision <n>` (손으로 상태 칸을 바꾸지 않음) |

- `accept` 는 결정로그 #n 이 체크포인트 「관문 인정」 행일 때만 상태를 바꾼다 (없으면 거절)
- `check` 를 다시 돌려 같은 점검이 같은 결과로 다시 걸리면 새 행도 「인정 (결정로그 #n)」으로 적는다 (결과가 달라지면 다시 미해결 · 사람에게 새로 물음)
- 셈: 미해결 · 미확인 · 인정을 따로 센다. 리포트 7절 · 뷰어는 「미해결 0 · 인정 n」처럼 나눠 보이고, 인정 행 때문에 CP5 를 「공유 승인 안 함」으로 적지 않는다
- 검증 담당은 인정 행을 다시 미해결로 바꾸지 않는다. 사람이 인정을 거두면 리드가 결정로그에 새 행을 적고 같은 점검을 다시 돌린다
