# wfp-step4-gap · ④ Gap · 대안

법전 근거: Gap 과 Gap Closing 우선순위 (D1-55) · 4B (D1-51 · D1-65 · D1-76) · Skill 장 FTC (D1-75) · 인접 스킬 겹침률 (D1-77) · 매칭 · 전환 · 육성/채용 사례 (D1-78~80) · Pivotal Role (D1-50). 법전 원문은 작업 폴더에 없다. 이 Skill 본문의 규칙만 쓰고 장 번호 · 기준을 지어내지 않는다.

## 절차

1. **Gap 표 · 스킬 근거 (스크립트)**: `python -X utf8 .claude/skills/wfp-step4-gap/scripts/step4.py run --co <회사>`
   - `④_Gap대안.md` 1절 (Gap 표 · 유형) · 4절 (시나리오 숫자) · 5절 (FTC · 인접 스킬 재배치 후보)을 쓴다. 2 · 3절 (대안 · 재배치)은 담당 칸이라 지우지 않는다
   - 스킬 인벤토리 두 시트 기준 연도가 다르면 「예외 · 스킬기준일」로 멈춘다 (섞지 않음)
2. **대안표 · 재배치 경로 작성 (담당 판단)**: 2 · 3절을 채운다
   - 행마다 4B 대안 · 시점 · 근거 (①_사업전략분석 요인 번호 또는 파일 1 절) · 경로 · 우선순위 · 2×2
   - **추가 자료** (`①_열대응표.md` 「추가 자료」 절 · `data/<회사>/추가_*`, 예: 교육 이수 · 자격 보유 · 외주 인원)는 판단 칸 · 4B 대안 근거로 「회사 기준 · 파일명」 표기해 인용할 수 있고 숫자 계산에는 쓰지 않는다 (Gap · 재배치 인원은 스크립트 숫자 그대로)
   - 여유 RPU 는 5절 인접 스킬 후보에서 받는 RPU · 인원 · 교육 기간 · 시점을 고른다 (겹침률 높은 · 같은 그룹 순)
   - **신설 조직 (사업 이벤트 RPU 코드)도 받는 RPU 로 올릴 수 있다.** 스킬 인벤토리 행이 없어 5절 표에는 나오지 않으므로 (5절 아래 「신설 조직」 줄), 근거는 파일 1 인력 운영 방향 문장 · 겹침률 칸은 「신설 · 스킬 행 없음」
   - **정수 규칙:** 인원 = 행마다 사람 여유 표시값 (소수 1자리)을 반올림한 정수 (0.5 올림). 3절 표 아래 「정수 처리」 줄에 행 합 · 여유 합 · 차이와 근거를 한 줄로 적는다 (1절 「정수 규칙 적용 시 합」과 같아야 함 · 반올림 한 번으로 정원을 확정하지 않고 조정 근거를 남김)
   - 교육 · 시점 칸을 비우지 않는다 (비면 검증 「확인 필요」). 교육 기간이 파일에 근거가 없으면 「가설」로 표시
   - ② 대사 판정이 「추가 확인 · 잠정 C」인 RPU 는 2절 그 행 근거에 「② 대사 추가 확인」을 적고 4B 를 확정하지 않는다 (「추가 확인」)
   - 4절 트리거 지표 (다시 돌릴 조건)를 적는다
   - **손 칸이 채워진 뒤 run 을 다시 돌리지 않는다.** 4절 손 칸 (Staffing 변화 · 트리거 지표)이 채워져 있으면 `step4.py run` 이 덮지 않고 「예외 · 손칸보호」로 멈춘다. 대안 · 경로를 고칠 때는 2 · 3 · 4절을 고치고 `check` 만 다시 돌린다. 앞 단계 숫자가 바뀌어 다시 계산해야 하면 리드에게 돌려주고, 사람이 확정하면 `--force` 로 다시 돌린 뒤 4절을 다시 채운다
3. **점검 (스크립트)**: `step4.py check --co <회사>` → 4B 빈칸 · 근거 빈칸 · 감원 단독 · 여유 RPU 경로 누락 · 2절 「승인」 칸 답 4종 밖 값을 잡는다 → 통과하면 **CP4 Gap 대안 승인**에서 멈춘다
4. **CP4 승인 범위:** 「## 승인」 표 「확정」 = 2절 모든 행 승인 (범위 전체). 행마다 다른 답만 2절 「승인」 칸에 (추가 확인 · 보류 · 이관 + 이유) · 빈칸 = CP4 답을 따름. 고친 행은 「확정」 + 이유 칸에 내용. `step4.py check` 와 `verify.py` 가 같은 기준으로 본다
   - 승인자 (자사 예 · 가설): 인사기획팀장 + R 1순위 행 소관 본부장 (받는 RPU 의 본부) · 나머지 행은 Y · G 계획 승인으로 이유 칸에 기록. 본부 이름은 파일 2 「본부」 열 그대로 쓴다

## 4B 해법별 질문

| 4B | 해법 | 질문 |
|---|---|---|
| Buy | 채용 | 내부 육성이 곤란한가 · 빨리 확보해야 하는가 |
| Build | 이동 · 승진 | 내부에 역량 갖춘 인력이 충분한가 · 다른 조직 확보에 지장이 없는가 |
| Build | 육성 | 핵심직무라 내부 인력이어야 하는가 · 필요 수준까지 걸리는 기간은 (FTC 충족률 · 숙련 기간) |
| Borrow | 고용형태 변경 · 외부 활용 | 꼭 FTE 여야 하는가 · Part Time · Outsourcing 으로 대체 가능한가 |
| Bot | AI · 자동화 | 업무 자체를 줄일 수 있는가 · 도입 시점이 Gap 시점보다 앞서는가 |

**조합 규칙:** 핵심직무 = Build 우선 · 시점 Gap = Buy · Borrow 병행 · 여유 RPU = 재배치 경로 먼저 · 육성으로 시점을 못 맞추는 스킬만 채용 · 외부로 넘긴다
**우선순위:** 영향 × 시급성 2×2 (R 1순위 · Y 2순위 · G 3순위)

**우선순위 · 시점 판단 (법전 Gap Closing 우선순위 · 육성 조기 착수)**
- **영향** = Gap 규모와 사업 차질 (Gap 이 크거나 신설 · 법령처럼 못 채우면 사업이 멈춤). Pivotal 후보인지는 영향 근거가 아니다 (조합 규칙 「핵심직무 = Build 우선」의 입력). 가정 구분이 「회사 가정」인 값도 CP2 에서 사람이 확정한 값이라 영향을 낮추지 않는다
- **시급성** = 착수 시점이 얼마나 가까운가. 착수 시점 = 필요 시점 − 확보 기간 (채용 · 교육 · 숙련). 법령 시행 · 신설 가동처럼 **시한이 정해진 시점 Gap** 이면서 착수가 지금 ~ 계획연도 상반기이면 높음
- 외부 위탁 유지 · 단계 내재화 (Borrow) 로 시한을 늦출 수 있는 Gap 은 영향이 커도 시급성을 낮게 본다 (계획 대응 · Y)
- **시점 칸 = 착수 시점**: 필요 시점에서 확보 기간을 거꾸로 뺀 분기를 적는다. 교육 기간이 짧은 이동 · 단기 보완도 필요 시점 앞으로 당겨 착수한다 (예: 교육 3개월 · 필요 시점이 계획연도 초면 그 앞 분기에 착수). 교육 기간이 파일에 없으면 「가설」로 적고 같은 방식으로 역산한다
- R 은 「영향 높음 × 시급 높음」만 · 행마다 2×2 칸에 영향 · 시급 근거 한 줄 (Gap · 필요 시점 · 확보 기간)

**유형 판정 (스크립트 · 고치지 않음):** 1절 「유형」은 `step4.py run` 이 정한다 (수량 · 시점 · 구조 · AI 활용 · 겹치면 함께 적음). 유형이 이상해 보이면 ②_수요파라미터.md 5절 (시점 이벤트) · 3절 (AI 적용)을 고쳐 다시 run 한다. `step4.py` 등 스크립트를 고치자고 리드 · 사람에게 제안하지 않는다 (계산 엔진 잠금 · 이상하면 「이관 · 하네스 관리자」)

## 금지

- **감원 대안을 단독으로 내지 않는다** (여유 인력은 재배치 경로부터) · 개인 단위 배치안 · 명단을 만들지 않는다
- CP4 승인 전에 리포트를 쓰지 않는다 · 디지털 FTE 를 Gap 에 넣지 않는다 (도입 계획 칸)

## 끝낼 때

- 리드에게 「Gap 합 · 상승 시 Gap · R 1순위 RPU · 재배치 인원 (정수 규칙 합 · 여유 합) · 재배치 후보 수 · check 결과」를 돌려준다
- 재배치 후보 수 = 5절 「인접 스킬 재배치 후보」 표 행 수 (같은 보내는 RPU 가 여러 행이면 행마다 셈 · 신설 조직 줄은 따로 적음)
